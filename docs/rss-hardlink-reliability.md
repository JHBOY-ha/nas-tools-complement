# RSS 动漫硬链接整理修复

## 行为变化

- 下载整理失败后保留任务，按 60 秒起步、最长 1 小时的退避间隔重试；仅成功时设置“已整理”。目录监控的识别任务同样保留失败队列，磁盘操作不再持有队列锁。
- 新的 qBittorrent/Transmission 下载任务使用 `NASTOOL_CTX_<随机标识>` 标签关联 `DOWNLOAD_CONTEXT` 数据表。保存的 RSS 作品信息在下载后继续用于整理，不再根据缩写文件名重新猜测作品。不要手动移除该标签。
- 季集与 RSS 冲突时不静默覆盖。只有完整的前季集数能证明绝对集号映射时才自动转换；合集不会把 RSS 单集号套给所有文件。
- ANIME 使用电视剧检索；LLM 直出 ID 必须属于本次外部候选并符合作品类型；冲突的旧类型缓存被忽略，负缓存不再阻止重试。
- Jellyfin 按 TMDB ID 合并所有条目及分页中的季集，支持单文件多集；再与本地媒体目录及实际仍存在的入库历史合并。
- 普通硬链接整理会利用有效入库记录避免跨盘重复入库。明确启用文件大小覆盖或手动强制整理时保留原有覆盖策略。
- 自动选盘检查文件系统设备号；硬链接覆盖先创建临时链接，再原子替换。转移到未识别目录的硬链接不再把源文件加入成功黑名单。

## 升级与限制

正常启动会创建新增的数据表，也提供了可重复执行的 Alembic 迁移。不修改旧下载历史，不清除已有“已整理”标签，不删除已有媒体。

作品身份关联从升级后的新下载任务开始。旧任务没有身份标签时仍走文件名识别；以前已被错误标记“已整理”的任务需要手动重新整理或移除该标记后重试。

任务标签丢失后无法可靠恢复下载身份；标签存在但数据库记录缺失时会报告错误，避免猜测。跨季/混合作品合集以及无法验证的集号映射需要人工核对。目录监控通过下载器文件清单精确复用身份，混合目录逐文件绑定；未完成任务保留重试。没有任务关联的文件仍按文件名识别。

## 验证

`python -m unittest tests.test_sync_reliability` 可离线运行针对生产方法的回归测试；测试通过 AST 加载方法以避免启动应用服务。覆盖多盘分页季集合并、RSS 身份传递、识别冲突、失败重试、真实硬链接替换和本地历史失效等场景。

另外在临时配置/数据库中验证了现有 LLM、中文兜底、元数据缓存测试，数据库会话关闭后的身份读取，以及 Alembic 的首次升级、重复升级和回退。

未连接真实 Jellyfin 或下载器执行端到端测试。

## 2026-09-17 日志回归修复

- 下载身份递归转换 TMDB AsObj，支持 genres、seasons、external_ids 等嵌套内容，避免 JSON 序列化阻止添加下载。
- 请求季不存在或集号超出范围时返回“无法确认”；自定义 RSS 和普通订阅保留待重试，不再判为已存在或继续下载。
- 动漫候选先过滤动画分类，再匹配同名作品；绑定前校验请求季，旧真人剧缓存不再直接复用。
- 经外部候选验证的 LLM 结果可纠正规则解析的默认电影类型，明确指定的类型仍优先。
- 目录监控按下载器文件清单绑定作品，拒绝多个任务争用同一文件；监控只看到合集的一个文件时，也不会套用 RSS 单集号。

旧任务没有身份记录时，目录同步会尝试用下载器哈希精确关联 `RSS_TORRENTS` 与 `DOWNLOAD_HISTORY`；两者无法唯一对应时仍需重新识别。已被错误识别后写入转移黑名单的文件，只要能建立这条精确关联也会重新处理。本次不修改线上缓存、历史或已下载文件。
